方案 07 · GRAPH VIEW · 對照組

Obsidian 式關係圖 V1 簡單版

照 Obsidian 的關係圖（Graph view）原樣，把共用資料中 24 個節點和 27 條有類型的關係畫成力導向圖：圓點按連結數放大，懸停時亮起鄰居，點選就開啟一則「筆記」，內有 [[wikilink]] 與反向連結。這是給團隊比較的對照組，刻意不作改良。

正式版的資料可以直接來自研究團隊的 Obsidian vault；若用作公眾入口，還要另備一個不靠圖形的清單版本。　看 V2 多維度版 →

Webflow 做法：節點和關係各為一個 CMS Collection（關係以兩個 Reference 欄位連到節點，動詞、時期、來源、狀態為欄位）。每則筆記用 CMS Template page 原生生成，Links 與 Backlinks 是按 Reference 篩選的 Collection List。關係圖本身必須放在 Code Embed：隱藏的 Collection List 輸出 data 屬性，由 d3-force 讀取繪製。

    這種圖擅長甚麼、不擅長甚麼

    以下是把水口資料原樣放進 Obsidian 關係圖後的觀察，供團隊討論。

    擅長 STRENGTHS

    1. 看到樞紐。圓點按連結數放大，一眼可見 村民、黃牛、水稻 是連結最多的筆記。
    2. 漫遊。沿 [[wikilink]] 與反向連結一則一則跳，容易遇上意料之外的連接，例如柴草、蔥、水稻和沙白都指向「瀨鑊邊」。
    3. 與研究工作吻合。每個節點就是一則筆記，關係可以寫成 Dataview 欄位（造棲地:: [[牛打滾的水氹]]），研究員在 Obsidian 內整理，網站讀同一份資料。
    4. 暴露缺口。孤立筆記（海膽）浮在外圍，提醒資料還沒有連上。

    不擅長 WEAKNESSES

    1. 沒有地方。位置由物理模擬決定，每次打開都不同；泥灘與林在圖上的距離沒有意義，檢查點完全看不到。
    2. 沒有時間。1960 年代的截水與今天水牛佔路畫成同一種灰線，容易讀成同時發生；「曾經」與「現在」無從分辨，也看不到節氣與潮汐。
    3. 沒有衝突，也沒有可信程度。「衝突」只是另一條灰線；村民口述與研究員觀察看起來一樣肯定，要點進筆記才見到狀態標籤。
    4. 圓點大小突出人類。按連結數放大，村民成為最大的圓點，與「人只是其中一條物種路線」的原則相反。
    5. 對公眾門檻高。要先明白點和線代表甚麼；手機上拖曳圖形與捲動頁面互相干擾；螢幕閱讀器只能逐點讀出名字。

    討論

    1. 關係圖應作為公眾入口，還是研究團隊內部的整理工具，再把資料供給其他方案？
    2. 如果保留，應放在哪一層？例如物種頁底部的局部圖（深度 1）。
    3. 節點大小應按連結數，還是由團隊決定？
