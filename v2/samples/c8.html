方案 08 · GRAPH VIEW · 何時與何地

Obsidian 式關係圖 V2 多維度版

同一份資料、同一種力導向圖，加上「何時」與「何地」兩組控制。拖動年代時間軸（或切換到二十四節氣的「一年之中」），再選一個地點，關係就會長出、結束，並留下「曾經」的點線；變化紀錄面板逐條列出新出現、消失與持續的關係，附來源與核實狀態。

「改良版」再把線按關係類型區分（點線是曾經，衝突色是衝突），並把有檢查點的節點拉向它們在地圖上的位置；也可切回「Obsidian 原樣」比較。年代分段與對應為示意，年代未核實。　看 V1 簡單版 →

Webflow 做法：節點、關係、檢查點、農事曆各為一個 CMS Collection；關係以 Reference 連到兩個節點和一個檢查點，所屬年代用五個 Switch 欄位記錄（Webflow 沒有多選 Option）。筆記頁與變化紀錄的文字可由 CMS 原生輸出；關係圖、時間軸、小地圖和過場動畫放在同一個 Code Embed，以 d3 讀取隱藏 Collection List 的 data 屬性。

      時期如何對應（示意，年代未核實）

      五段年代按共用資料的因果鏈命名。每條關係在 data.js 只有一個籠統的「時期」說法，下表是本頁把它歸入哪幾段的判斷，需要團隊確認。

      季節取自村民對耕作年代的口述（保留原本的農曆說法），今天不一定如此。節氣日期為 2026 年約數。亮起的節點表示此節氣有相關活動；連線亮起只表示與該節點相關，不代表關係只在此季節發生。

      V2 補上了甚麼，仍欠甚麼

      與方案 07 的原樣關係圖比較，供團隊討論。

      補上的 ADDED

      1. 時間。五段年代與二十四節氣兩種尺度。關係會長出、結束，結束後留下「曾經」的點線；沒有關係的節點縮小變灰。
      2. 可讀的變化。變化紀錄面板把每一步寫成清單（新出現、消失、持續），附來源與核實狀態。真正讓人看懂變化的是這份清單，圖形負責整體印象。
      3. 地點。選地點或點小地圖，只亮起在該處記錄的關係；改良版中有檢查點的五個節點被拉向地圖位置，地名放在背景。
      4. 關係類型與衝突。線按動詞分類，「衝突」用衝突色並常駐標籤，「曾經」用點線，懸停可見動詞與來源。

      仍欠的與風險 LIMITS

      1. 年代對應是本頁的判斷。data.js 的「過去」「近年」等說法沒有確切年份；對應表（時間軸下）需要團隊確認。
      2. 「消失」可能只是資料缺口。例如「棄耕」一段只有 3 條關係，是因為訪談較少談及這段時期，不代表那時沒有關係。增減不等於好壞。
      3. 兩套時間未能合併。節氣模式只按村民對耕作年代的口述點亮節點，與年代軸各自獨立；潮汐仍未加入。
      4. 地理拉力只作用於五個節點。其餘節點的位置仍由物理模擬決定；海一側的距離已壓縮。
      5. 控制項多。時間、地點、兩種模式加設定抽屜，對公眾可能太複雜；正式版或應預設一條導覽，例如打開時自動播放一次年代。

      討論

      1. 年代對應表是否合理？「過去」應否只屬耕作期？
      2. 公眾版保留 A、B 兩種模式，還是只保留改良版？
      3. 變化紀錄可否成為主體，圖形退為插圖？
